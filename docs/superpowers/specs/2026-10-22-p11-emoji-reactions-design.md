# P11 — 게임 중 이모지 반응 설계

- 작성일: 2026-10-22
- 상태: 설계
- 선행: P10 빠른 전달과 순간 상태 (`2026-10-22-p10-realtime-fast-path-live-design.md`)
- 범위: 네 게임(요트·오목·컵퐁·알까기)의 온라인 대전에서 게임 도중과 판이 끝나 결과 카드가 떠 있는 동안 아이폰 기본 이모지를 상대에게 보내고 받는 것. 글자 채팅, 저장, 푸시 알림, 서버 변경은 범위 밖이다.

## 1. 목표

온라인 대전에는 수 말고는 상대에게 무언가를 전할 길이 없어 잘 둔 수에 감탄하거나 아쉬움을 드러낼 수 없으므로, 게임 도중 아이폰 기본 이모지라면 어떤 것이든(피부색, 국기, 가족처럼 여러 글자가 이어진 조합 포함) 상대에게 보내게 하고, 받는 쪽 화면에서는 판 위로 크게 떠올랐다 흩어진 뒤 보낸 사람의 명패 모서리에 배지로 남게 한다.

성공은 세 가지로 잰다. 보낸 이모지가 상대 화면에 0.3초 안에 떠올라야 하고, 시스템 이모지 키보드에서 고를 수 있는 이모지는 모두 보낼 수 있어야 하며, 이모지가 아닌 글자는 어떤 경로로도 상대 화면에 나타나지 않아야 한다.

## 2. 하지 않는 것과 해서는 안 되는 것

- 하지 않는다: 글자 채팅, 반응의 저장이나 기록, 앱이 닫힌 상대에게 보내는 알림, 같은 기기 2인 대전과 컴퓨터 대전에서의 반응, 앱이 따로 두는 자주 쓰는 이모지 목록(시스템 키보드의 "자주 사용하는 항목"을 그대로 쓴다), 서버 정책·마이그레이션 변경.
- 해서는 안 된다: 이모지 기능이 글자를 주고받는 통로가 되는 것, 반응이 수·로그·`throws`·전적에 섞이는 것, 떠오르는 이모지가 판 입력을 막는 것, 반응 때문에 무료 티어의 초당 메시지 한도가 위태로워지는 것, 빌드 11 이하나 P10 빌드 상대와의 대전이 깨지는 것.

## 3. 결정

| 항목 | 결정 |
|---|---|
| 보내는 곳 | 네 게임 화면 머리글의 오른쪽 끝에 😊 단추를 두며 온라인 대전일 때만 보인다. 판이 끝나도 그 화면에 있는 동안은 단추가 남아 "GG"처럼 결과 카드 위에서도 주고받는다 |
| 입력 | 단추를 누르면 화면에 보이지 않는 입력 칸이 시스템 이모지 키보드로 열리고, 이모지 하나가 입력되는 순간 보내고 키보드를 닫는다. 키보드 밖을 누르거나 단추를 다시 누르면 보내지 않고 닫는다 |
| 이모지 판정 | 한 글자(Swift `Character` 하나)이고 이모지로 그려지는 것만 받으며, UTF-8로 64바이트를 넘으면 버린다. 보내는 쪽과 받는 쪽이 같은 판정을 쓴다 |
| 전송 | 이미 구독 중인 비공개 채널 `match:<id>`의 클라이언트 브로드캐스트 `emoji`로 `{"emoji": "🔥", "event_count": n}`을 보낸다. `event_count`는 보낸 순간 보낸 사람 로그의 수·이벤트 개수다. 저장하지 않고, 구독 중이 아니면 보내지 않는다 |
| 빈도 | 보내는 쪽은 마지막으로 보낸 뒤 1초가 지나야 다시 보낼 수 있고 그동안 단추를 흐리게 잠근다. 받는 쪽도 같은 사람에게서 1초 안에 온 둘째 이모지는 버린다 |
| 받는 쪽 연출 | 판 가운데에서 크게(64pt) 떠올라 위로 흩어지며 2초 안에 사라지고, 그 뒤에는 보낸 사람 명패 오른쪽 위 모서리에 작은 원형 배지로 남는다. 떠오르는 이모지는 입력을 받지 않는다 |
| 보낸 쪽 연출 | 보낸 사람 화면에도 같은 연출을 보이고 배지는 자기 명패에 붙는다 |
| 배지 수명 | 같은 사람의 다음 이모지가 오면 그것으로 바뀌고, 보낸 순간의 수 뒤에 처음 차례가 바뀌면 사라진다(내 결정). 받는 쪽이 보낸 사람의 수를 아직 재생하고 있어도 두 화면이 같은 수에서 배지를 지운다 |
| 동작 줄이기 | 시스템의 동작 줄이기가 켜져 있으면 떠오르지 않고 제자리에서 나타났다 사라지며 배지는 같다 |
| 접근성 | 단추 라벨은 "이모지 보내기"이고, VoiceOver가 켜져 있으면 받을 때 "<보낸 사람 이름>: <이모지>"를 알린다 |
| 진동 | 받을 때 기존 `Haptics`로 가벼운 선택 진동을 한 번 내고 효과음은 없다 |

## 4. 앱

### 4.1 전송 계층

`TurnTransport`에 반응 송수신을 더하고 기본 구현은 아무것도 하지 않는다.

```swift
protocol TurnTransport: Sendable {
    // 기존 멤버는 그대로다
    /// 이모지 반응. 저장하지 않으며 놓쳐도 판에 영향이 없다.
    func sendReaction(_ reaction: Reaction) async
    var reactions: AsyncStream<Reaction> { get }
}

struct Reaction: Sendable, Equatable {
    let emoji: String
    /// 보낸 순간 보낸 사람 로그의 수·이벤트 개수. 배지를 지울 때를 두 화면이 같게 정한다.
    let eventCount: Int
}
```

`SupabaseTurnTransport`는 P10의 `live`와 같은 방식으로 채널이 `subscribed`일 때만 `emoji` 이벤트를 보내고 `broadcastStream(event: "emoji")`의 `payload`를 `Reaction`으로 흘리며, `InMemoryTurnTransport`는 짝에게 그대로 넘기고 보낸 것을 기록한다. 받는 스트림은 가장 최근 몇 개만 버퍼에 둔다. P10 마이그레이션이 참가자의 모든 브로드캐스트를 허용하므로 서버는 바꾸지 않는다.

### 4.2 `ReactionBoard`

요트의 `GameSession`과 나머지 게임의 `OnlineMatch<G>`가 같은 것을 쓰도록, 반응의 판정·빈도·표시 상태를 `@MainActor @Observable final class ReactionBoard`(`App/Game/ReactionBoard.swift`) 하나가 맡는다.

- 만들 때 내 좌석, 상대 좌석, 상대 이름, 전송을 받는다. 두 세션은 온라인일 때만 이것을 만들어 `reactions`로 내놓고, 로컬 대전에서는 nil이라 화면이 단추를 숨긴다.
- `send(_ text: String) -> Bool`은 판정과 1초 제한을 통과하면 전송하고 내 좌석으로 연출을 띄운 뒤 참을 준다.
- 받기 루프는 세션의 `startListening()`이 시작하고 `stop()`이 접으며, 판정을 통과하고 같은 사람의 1초 제한에 걸리지 않은 것만 상대 좌석으로 띄운다.
- 화면이 읽는 상태는 지금 떠오르는 반응 목록(식별자, 이모지, 좌석, 시작 시각)과 좌석별 배지다. 떠오르는 반응은 2초가 지나면 목록에서 빠진다.
- 배지는 반응의 `eventCount`를 함께 든다. `noteTurn(_ seat: Int?, eventCount: Int)`는 세션이 로그나 보이는 상태를 바꿀 때마다 지금 차례와 로그의 수를 알리고, 차례가 이전과 다르면 그 수를 "마지막으로 차례가 바뀐 수"로 기억해 그보다 작은 `eventCount`의 배지를 지운다. 보낸 사람이 빗나간 직후(차례가 바뀐 수 N에서) 보낸 이모지는 양쪽 모두 N 다음에 차례가 바뀔 때 사라진다. 판이 끝나면 더 바뀔 차례가 없으므로, 끝난 뒤의 배지는 같은 사람의 다음 이모지로만 바뀐다.

이모지 판정은 순수 함수 `ReactionBoard.isSingleEmoji(_:)`로 두어 테스트한다.

### 4.3 화면

겹층은 각 게임의 판(요트는 주사위 무대) 위에 얹고 `allowsHitTesting(false)`로 입력을 지나가게 하며, 머리글의 기존 요소(턴·상태 글자)는 단추가 들어갈 자리만큼 줄일 뿐 없애지 않는다. 접근성 식별자는 단추 `reaction.button`, 떠오르는 이모지 `reaction.burst`, 배지 `reaction.badge.<좌석>`이다.

## 5. 호환

빌드 11 이하와 P10 빌드는 `emoji` 이벤트를 구독하지 않으므로 받지 못할 뿐 판은 그대로 이어지며, 새 앱끼리만 반응이 오간다.

## 6. 테스트

| 대상 | 테스트 |
|---|---|
| 판정 | 단위: 🔥, 👍🏽, 🇰🇷, 👨‍👩‍👧‍👦, 1️⃣, ❤️는 참이고 "a", "1", "🔥🔥", "", "🔥a", 64바이트를 넘는 문자열은 거짓이다 |
| 보내기 | 단위: 보내면 전송에 그 이모지가 가고 내 좌석으로 떠오르며 내 명패에 배지가 붙고, 1초 안의 둘째는 보내지 않고 거짓을 준다 |
| 받기 | 단위: 받으면 상대 좌석으로 떠오르고 배지가 붙으며, 이모지가 아닌 것과 같은 사람의 1초 안 둘째는 버린다 |
| 수명 | 단위: 떠오르는 반응은 2초 뒤 목록에서 빠지고, 배지는 보낸 수 뒤에 차례가 바뀌면 사라지며 같은 차례에서는 남는다. 받는 쪽이 보낸 사람의 앞선 수를 재생하는 중에 받은 배지는 재생이 끝나 차례가 바뀌어도 남는다 |
| 세션 | 단위: 온라인 `OnlineMatch`와 `GameSession`은 `reactions`를 내놓고 로컬은 nil이며, 상대 수를 재생해 차례가 바뀌면 배지가 사라지고, 판이 끝난 뒤에도 주고받을 수 있다 |
| 전송 | 단위: 메모리 전송이 짝에게만 넘긴다. 통합: 호스트가 보낸 이모지가 게스트 스트림에 닿는다(익명 가입 한도를 아끼려 기존 접속 테스트의 쌍을 쓴다) |
| 화면 | UI: 로컬 오목에서는 `reaction.button`이 없다. 시뮬레이터 두 대로 네 게임의 단추·키보드·떠오름·배지를 눈으로 확인한다 |

## 7. 치르는 값

- 상대가 그 판 화면을 보고 있지 않으면 반응을 받지 못하고 나중에 다시 볼 수도 없다.
- 설정에서 이모지 키보드를 지운 사용자는 단추를 눌러도 기본 키보드가 열리며, 그때 친 글자는 보내지지 않는다.
- 조작된 클라이언트는 1초 제한을 무시하고 보낼 수 있어, 받는 쪽 화면에는 걸러지더라도 Realtime 메시지 수에는 잡힌다.
